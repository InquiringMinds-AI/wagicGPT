# deck130 - proposals for the strategy-writing skill (wave 50)

Each proposal names its evidence; synthesis owns adoption.

**S1 - A render outcome that exists on one row family and not on its sibling is a guide hazard,
and the guide names which rows print the result and which do not.** Spell target menus print
`{right now: takes N damage - DIES / SURVIVES (toughness T)}`; the activated-ability rows
(`Deal 2 damage with Siege-Gang Commander targeting ...`, Spellbomb the same) print nothing - 0 of
49 this corpus. The pilot, trained by the spell rows to read a result, fired 2 damage at a 3/4 at
4 life (130v162 seq 23) and at 3 loyalty (seq 17). Rule: the #128 grep is run per ROW FAMILY - for
each annotation a guide relies on, list the row families that print it and the ones that do not,
and where a family lacks it the guide says "these rows print no result; read the (P/T) yourself"
until the render half ships (D50-5; seat H2).

**S2 - A menu with no exit is taught with the exit one screen earlier, and the exit row is
quoted.** The X menu after `Cast Card Normally` spends the card on every row; the (a)/(b) rules
were obeyed at the cast row 5 times in one game and broken at the X menu once the pilot had
committed (130v126 seq 60, "without killing Siege-Gang Commander" written beside `YOURS: Siege-Gang
Commander`). The `Choose an option` menu's `Decline - do nothing` row was never quoted in the
guide. Rule: for any two-screen commit (cast row -> option menu -> X menu; Tutor -> reveal list),
the guide states the last screen on which "cast nothing" is still an answer, quotes the exit row's
literal, and says the screens after it have none (D50-4, D50-8).

**S3 - A check that exists in another deck's guide for the same opposing cards is ported when the
matchup is in the pool, keyed to the same tag.** deck123's CHECK 1 has priced Perimeter Captain /
Pride Guardian since wave 45; deck130 met the same two walls at 130v126 seq 49 and handed over nine
life with `(blocking trigger: they may gain 2)` printed on every attacker tag. Rule: at step 1
(read the deck) the reviewer lists the pool's named-card checks in the OTHER guides and confirms
each is present or inapplicable in this one - the tag string is the same for every seat, so the
sentence ports verbatim (D50-7).

**S4 - "One blocker stops one attacker's damage" is stated with its scope, because the render
prices a second question on the same header.** The guide's anti-triple-block rule (wave 48) was
read at 130v162 seq 22 as a ban on the kill the header priced (`GANG BLOCK: your 3 biggest together
deal 4, enough to kill this attacker`), at 7 life against a draw punisher, the turn before the draw
step killed the seat. Rule (extends #122's "state the post-action quantity"): a damage-prevention
rule names the quantity it governs (damage) and the sibling quantity it does not (a kill the
header prices), and the kill case is written with its own condition - the attacker's identity
(punisher / only clock) and the life after its `deals N` (D50-6).

**S5 - A rule that fails identically in a third corpus with the reply quoting the guide's own
arithmetic routes to the render and keeps one line.** Hammer return with the Commander in hand:
wave 48, wave 49 (x2), wave 50 (130v123 seq 18, the reply's plan saying "wait, I have 5 mana ... so
I can cast it" and taking the return anyway). Same as deck123's S6: the seat file carries the render
ask (M3), the guide gets its specimen and nothing more (D50-1). The pattern across both seats this
wave: a rule keyed correctly to the screen, quoted back by the pilot, and broken in the same reply -
the executor is not failing to see, it is failing to sequence, and sequence is a render/protocol
lever (the upkeep ask arrives before the main-phase menu exists), not a prose lever.
