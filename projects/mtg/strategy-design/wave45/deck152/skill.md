# deck152 — proposals for the strategy-writing skill (wave-45 evidence only)

## S-E. A RENDER LANE THAT SHIPS CREATES A GUIDE OBLIGATION IN EVERY GUIDE, THE SAME WAVE
The wave-45 lane-A `GANG BLOCK:` clause priced deck152's fatal attack exactly and in advance
("their 6 biggest together deal 7, enough to kill this attacker"), and deck152's guide contains no
rule keyed to it — because in wave 44 only deck162 had seen the collapsed form, so only deck162 got
the teach. The string is pool-wide; the teach was not. Amendment #32 already says a rule keyed to a
RENDER STRING is pool-wide and asks for a cross-guide index; this corpus shows the index has to be
maintained in the OTHER direction too.
PROPOSAL: make it a step-1 deliverable. **When an engine lane ships a new rendered string, the lane
report names every guide in the pool that can see it, and the seat reviewers for those guides are
required to answer "rule present / rule absent / not applicable" for their decks in the same wave.**
A newly rendered fact with no consumer is the most expensive kind of engine work: it cost a card,
a board and a game here while displaying the right answer.

## S-F. WHEN A PARENTHESIS CARRIES A BENEFIT, THE GUIDE MUST SAY THE BENEFIT IS *INSTEAD OF*, NOT *AS WELL AS*
deck152's reply at vs162 seq 28: "The Intrepid Adversaries gain 3 life each via lifelink (total +6
life) and deal 6 damage to the opponent." The tag it was reading said "(your attacker dies, their
blocker lives (lifelink: you gain 3))". The model added the blocked branch's payout to the unblocked
branch's damage. Amendment #30 found the same shape with vigilance (a keyword removing a stated
cost); this is its complement — a keyword adding a stated benefit inside the stop's own parenthesis.
PROPOSAL: generalise #30 to a two-sided check. **For every stop keyed to a rendered outcome, list
the keywords that can appear INSIDE that outcome's parentheses (lifelink, deathtouch, trample,
first strike, infect) and state, for each, whether it changes the verdict — and where the keyword
prints a number, say explicitly which branch that number belongs to.** A parenthesis that mixes a
bad outcome with a good number is the single most reliable way to lose a rule.

## S-G. A RELEASE CONDITION BELONGS ABOVE THE PROCEDURE IT RELEASES, NOT BELOW IT
deck152 answered `BLOCKS: none` twice in one ten-turn game — once past a "(both die)" and once at
"you would be at 5" with a floor of 9 — and both replies were two lines long with no reference to
the ladder at all. The permission to answer none is the LAST line of a 25-line ladder. The model
never got there.
PROPOSAL: extend amendment #24's "the clause nearest the decision wins" into a placement rule.
**State the null answer's precondition BEFORE the procedure, as the first thing the section says,
and phrase it as one comparison against a printed number.** A procedure whose exit condition is
buried at the bottom will be exited before it is entered. Related and cheap: a review check for
"answers that skipped the procedure" — a `BLOCKS:` reply that never mentions the header's own
"you would be at N" number is measurable and was 2 for 2 here.

## S-H. CONNECTION TEACHES NEED A CONCENTRATION CLAUSE
Wave 44's counter-placement teach worked (5 placements, 0 onto a Fog-Bank-walled body, two onto a
flier). The same corpus then lost a game because seven counters went onto one body which died to a
gang block. The teach asked the right question ("can this body connect?") and had nothing to say
about putting everything in one basket.
PROPOSAL: any recurring "choose a target for your own recurring buff" rule gets both questions:
first CONNECTION (does that body's tag get through?), then CONCENTRATION (is that body already
carrying so much that one answer takes all of it?). One line each.
