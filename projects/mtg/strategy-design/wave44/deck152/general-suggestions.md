## G-5 (MED, prompt text) — the LETHAL block header states the goal but gives no method
Current text: "Your life: 6. Unblocked, these attackers deal up to 11 - you would be at -5 -
LETHAL if it all connects (at 0 life you LOSE - 0 is not survival): block enough to survive."
"Block enough to survive" is the right instruction and the model still picked the free kill,
because nothing in the header connects each attacker's own "deals N" to the surplus that must be
removed. Repro: deck152 vs deck146 seq 20.
PROPOSAL: on LETHAL headers only, print the surplus and the sorted damages, e.g.
"You must stop at least 6 of the 11: A2 deals 7, A1 deals 2, A3 deals 2."
This is arithmetic the engine already has, it stays a statement about the board (no strategy
advice), and it puts the deciding number next to the decision instead of leaving it to be summed.

## G-6 (MED, prompt text) — CHOICE replies to mode-label asks are the fallback population
All 6 fallbacks in the whole corpus are on my three seats; 5 are `stale_echo`. The subclass:
57 asks corpus-wide whose option rows are bare MODE LABELS carrying no card identity
("creature gains 3/3 and sacrifice creature", "choose a land", "choose your land"), plus
damage-assignment lists of identical names ("Vampire (2/2)" x3). Fallback rate on that subclass
7.0% vs 0.29% overall. The reply protocol demands "the number of your choice and its SHORT NAME
in parentheses"; these lists have no short name to copy, so the model writes the SOURCE card's
name and the echo pass finds no matching option.
PROPOSAL (prompt text, not engine): on an ask whose options carry no card name, replace the
example line with one that shows the mode text being copied, e.g.
`e.g. "CHOICE: 2 (you draw and sacrifice creature)" - copy the option's own words`.
The engine-side half (accept an echo naming the ask's own SOURCE) is in the seat file as E-3.

## G-7 (LOW, prompt text) — the sub-ask does not say what the parent decision was
