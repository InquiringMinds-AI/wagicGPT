# ENGINE / RENDER ITEMS (ranked)

**H1 (HIGH) - the "Announce the value of X" menu is inverted and carries no annotation.**
The row reads `option 1 is the LARGEST X (X = 5)` and the pilot answers `CHOICE: 1` meaning
X=1. It cost deck130 a game it was winning.
Repro: `1787761212-ai_baka_deck130-0x55df6ecbf9d0-vs-ai_baka_deck126.jsonl`, seq 45
(plan states X=1) -> seq 46 (`CHOICE: 1 (Starstorm)`, which is X=5), against the seq 44 row
whose annotation reads `At X=5 ... YOURS: Rorix Bladewing`.
Corpus-wide denominator: 18 X-announce windows, 2 with a plan-stated X that differs from the
chosen X, BOTH toward option 1 (the other is deck125 seq 83, plan X=4, chose X=11). 11%.
Two independent fixes, either sufficient: (a) order the options ASCENDING so option N = X = N
where affordable, or (b) repeat the `{X pricing:}` kill preview on each option row - minimally
the `kills YOURS: ...` half, which is the half that loses games. (b) is strictly better: the
announce menu is currently the only decision in the game where the pilot picks a number with
NO consequence preview at all, having seen one on the previous screen.

**H2 (HIGH) - combat previews model deaths and never model LIFE.**
`[their untapped blockers: Perimeter Captain (0/4) (neither dies)]` is true and lethally
incomplete: blocking with that creature gains its controller 2 life per Captain and, through
Sanguine Bond, takes that much off the attacker. deck123 died to this twice in one game while
its own reply quoted both card names. Same class as the known E-3 item ("(both die)" omits
blocker lifelink), one step larger: the omission is not a keyword on the blocker, it is a
triggered ability on a THIRD permanent.
Repro: `1787761184-ai_baka_deck123-0x55e881efea80-vs-ai_baka_deck126.jsonl` seq 40 and seq 59.
Ask: when any opponent permanent has a `@combat(blocking)`-triggered life gain, or a
`@lifeof(player)` conversion enchantment is on either battlefield, the attackers prompt should
carry one line stating the per-block life swing - e.g.
`[if they block with N defenders: they gain 2N x (Captains), you lose that much x (Bonds)]`.
Not prose in the guide: the guide cannot compute a board it is not shown.

**M3 (MED) - the plan-mismatch note over-fires on a verb, and is noise at 34%.**
193 fires in 562 records; 52 (27%) name an object present in the menu under the engine's own
verb rather than the pilot's. The remaining 141 mostly fire because the plan legitimately
names NEXT TURN's actions - a plan is a multi-turn object and the note treats it as a
this-menu object. Attackers/blockers are clean (0/14), which is the wave-43 ask discharged.
Repro: deck123 vs162 seq 48 (plan "Tap Lord of Lineage to create a Vampire token", options
`Create vampire with Lord of Lineage #1/#2`).
Ask: match on the plan's CARD NAMES against the menu's card names before firing, and suppress
on any plan clause that begins "Next turn" / "Then".

**M4 (MED) - opponent non-creature permanents carry no text anywhere on the prompt.**
The opponent battlefield line prints `Sanguine Bond {3}{b}{b} [enchantment]`,
`Staff of Nin {6} [artifact]`, `Howling Mine {2} [artifact]`, `Lightmine Field {2}{w}{w}
[enchantment]` - name and type only. Target rows DO carry `{target text:}` (#W44-3, 53/53), so
the channel exists and is simply not applied to the board line. Every card in that list changed
or ended a game at these seats. The pilot currently recalls them from training, which is exactly
the failure mode #W44-3 was filed to remove on the removal lane.
Repro: deck123 vs125 seq 50 (Staff of Nin x2, Lightmine Field, 0 text); deck123 vs126 seq 40.
Ask: an `{effect:}` clause on opponent permanents whose primitive has an `auto=` line, at least
for `@combat`, `@lifeof`, `@each ... upkeep` and damage triggers.

**L5 (LOW) - a malformed double assignment is accepted silently.**
deck130 vs146 seq 32 replied `BLOCKS: B1:A2, B1:none` - the same blocker assigned twice. The
parser took the first and moved on with no `fallback` flag. Correct in the safe direction, but
it means a self-contradicting block reply is invisible in the corpus. Worth a counter, not a
reject.
