# Wave 70 — instruction + parser audit against invariant 000

**Scope:** read-only inventory of every string the model is shown about HOW TO ANSWER and every
function that reads a reply, judged against ONE ruling. No fixes applied. Line numbers are from
the working tree on 2026-09-06 (`src/AIPlayerGPT.cpp` 77,365 lines).

**The ruling (owner, 2026-09-06; skill invariant 000):** reasoning happens ONLY in the model's
native reasoning channel (thinking ON, captured off `reasoning_content` so reviewers can read it);
the reply is the PLAN line and then the action line (CHOICE:/ATTACK:/BLOCKS:/PUT:), NOTHING else;
"the model CANNOT be told to write nonsense OR IT FUCKING WILL WRITE NONSENSE" — no instruction may
license prose in the reply, and no parser tolerance may exist that teaches the model prose is
accepted. Per-seam `max_tokens` caps never bound reasoning tokens.

**Two owner clarifications applied (invariant 000 (e)/(f), relayed 2026-09-06):**
(e) *PLAN purpose*, verbatim: "the purpose of the plan is to allow the model a scratchpad so it can
execute sequenced decisions. 'swing all, use combat trick n after blockers are declared, then play
creature in second main' something like that." So the PLAN is a SHORT ORDERED SEQUENCE of intended
actions across the coming windows, carried forward so each later window executes the next step; the
action line is step one; the PLAN is never reasoning or prose. Every plan-handling surface below is
judged by one test: does it preserve and carry a SEQUENCE, or does it treat the PLAN as reasoning
text? (f) *Regimes*: the PRODUCT regime is thinking OFF ("the primary expected method for use by
actual users is thinking off"); thinking ON is the dev/corpus regime so reviewers can read the
reasoning. The reply shape (PLAN then action, nothing else) is IDENTICAL in both; in thinking-off the
PLAN is the only conditioning the action gets. Sections C and D are written for both regimes.

**The finding that triggered it, verified in code:** `tools/selfplay-harness.sh:78` sets
`THINKING=0`; line 196 exports `WAGIC_GPT_THINKING="$THINKING"`; `AIPlayerGPT.cpp:15890` reads it
(`envFlag` → false); `GptConfig.cpp:50` defaults `thinking(-1)` so `cfg.thinking == 1` is also
false; `AIPlayerGPT.cpp:31642` then sends `chat_template_kwargs.enable_thinking: false`
UNCONDITIONALLY (the comment at 31634-31640 says the server default is thinking ON and this line is
what turns it off). So every corpus launched through the harness without `--thinking` reasoned
in-band, and the protocol + parsers below were tuned to that symptom.

**Verdict legend.** KEEP = consistent with PLAN-then-action under native thinking, licenses no
prose. CHANGE = licenses or assumes something the ruling forbids; minimal rewrite stated.
DELETE = exists only to tolerate in-band reasoning. VERIFY (Table B only) = behaviour depends on
what the model actually writes with thinking on; decide from the probe corpus.
