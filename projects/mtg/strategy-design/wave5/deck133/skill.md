# Wave-5 proposed revisions to the strategy-writing skill (from the deck133 seat)

The skill is comprehensive and its wave-4 additions held up well against this
corpus. One genuinely new pattern this wave earns a method line; the rest is "no
change."

## Proposed addition: PREFER an engine-SURFACED number over a hand-computed one — and verify its OFFSET.

The skill's numeric-offset trap (Step 2) covers index-vs-value on menus. This
corpus surfaced a sibling: the engine now embeds a **computed value inside the
option text** — Gray Merchant renders `{right now: drains N}`. That is strictly
better for a weak executor than the guide's hand-summed devotion formula (which
the pilot fumbled: vs110 it mis-added devotion and, separately, its wins show it
trusting the shown number over its own arithmetic). So the method should say:

> When the engine DISPLAYS a computed value in the option text (a drain amount, an
> X, a resulting P/T), teach the pilot to READ it rather than recompute — a number
> the pilot can see beats a formula it must run. But before shipping the read,
> VERIFY the displayed value against the RESOLVED result across every instance in
> the corpus: engine displays can carry a systematic offset (Gray Merchant's
> `drains N` under-counts by 2 because the card itself is not yet on the
> battlefield when the option is built; verified +2 in 3/3 casts). If there is an
> offset, either state the correction in the guide as a stopgap (with the
> display-fix removal condition) or route the fix to representation. Same audit
> discipline as the index-vs-value tell; the surface is different.

This slots next to "TEACH THE MENU" and the numeric-offset trap in Step 5 / Step 2.

## Proposed sharpening (minor): a card with TWO distinct uses needs TWO distinct triggers.

Gray Merchant is a lethal finisher AND a life-gain stabilizer; the wave-4 guide
gave it only the lethal trigger (drain >= opp life), so the pilot never fired it
as a survival button and died at 1 life with it castable (vs110 seq34). The weak
executor learns exactly the trigger you write and no adjacent use. Worth one line
under "Give arithmetic it can run":

> When a single card has two distinct correct uses (a burn spell that is also
> reach; a drain that is also lifegain; a creature that is also a blocker), write
> a SEPARATE keyed trigger for each use. The executor generalizes none of them —
> it fires only the use you spelled out, and misses the card in the other role.
