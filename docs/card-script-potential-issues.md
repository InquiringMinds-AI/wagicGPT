| CS-012 | **Fixed — engine** | Targeted `@energizedof` payload | Reproducer built (`trigger_energized_targeted_counter.txt`): the trigger's StackAbility goes on the stack and RESOLVES WITHOUT ever opening/waiting on its target chooser — clicks before resolution are consumed as interrupt-declines, so the counter payload fizzles targetless. Not a suite artifact (the wait never happens, so GUI play cannot answer either), and not payload word order (leading `target(...)` form fails identically). ROOT CAUSE UNDERSTOOD: creature-ETB payloads (bare `auto=`, e.g. Flametongue Kavu) route through the SPELL flow, which acquires targets at cast; `@event` trigger payloads route through GenericTriggeredAbility::resolve, which has NO target-acquisition step — a one-shot payload resolves immediately with an empty chooser and fizzles. Systemic and now MEASURED: 417 primitives use the plain (non-may) `@trigger:target(...)` shape vs 175 may-wrapped (which work via MayAbility). Spot checks fizzle 2/2 across unrelated trigger families: Fabrication Module (@energizedof) and Akoum Hellkite landfall (@movedTo — dealt 0 damage). The ability$!...!$ grant subfamily (Abyssal Specter discards) may work through the granted-activated path — verify before counting it broken. FIXED: `GenericTriggeredAbility::resolve` now routes payloads carrying an unfilled interactive action-TC (targetter set, not a TriggerTargetChooser) through `MayAbility(must=true)` — the same machinery the parser builds for `may target(...)` payloads — so the controller acquires the target; no legal target = the trigger correctly does nothing. Validated: both witnesses green (Fabrication Module counter, Akoum Hellkite landfall damage), full suite 994+4/0 with zero regressions, Baka self-play one-shot completes clean with the menus live. CS-005 (Circular Logic resolving before its payment menu) may be the same resolve-without-wait family. | Reproducer in `_potential_tests.txt`. |
